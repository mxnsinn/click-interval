# Server Enchantments — Fabric 26.2

Data-driven enchantments for dedicated servers and integrated single-player worlds. Install on the dedicated server, or in the Fabric client's mods folder for single-player. Dedicated-server players do not need to install it themselves. Names are literal text, so a client resource pack is unnecessary.

- **Tree Chop**: axes only, level I. Break a natural tree log to harvest its connected matching logs immediately when the shared work budget allows. Each additional log uses vanilla player block breaking, including drops, durability and Unbreaking. Sneak to mine only one log.
- **Miner's Sweep I**: pickaxes only. Mines a horizontal three-by-one row centered on the block you break: one block to either side, oriented along the hit face. On a top/bottom face, your horizontal facing chooses the row orientation.
- **Miner's Sweep II**: pickaxes only. Mines a three-by-three plane centered on the block you break, for nine total blocks. The plane follows the actual hit face: a vertical square on a wall, or a horizontal square when mining a floor/ceiling. It does not increase depth or add a Fortune bonus. Sneak to bypass either level.
- **Harvester Sweep I / II / III**: hoes only. Harvests ripe wheat, carrots, potatoes and beetroot in a horizontal three-block row / 3×3 square / 5×5 square centered on the crop you break. The row runs across your horizontal facing. Immature crops and unrelated blocks are left alone. Levels II and III replant using one matching planting item already in your inventory for each successfully replanted crop; level I never replants. No seeds means harvesting without replanting. Sneak to harvest just one crop without automatic replanting.
- **Smelter**: pickaxes only, one level. Converts the actual mined drops through the world's furnace recipes, after Fortune has determined their quantity. Works alongside Miner's Sweep. Unsmeltable drops stay unchanged, there is no recursive smelting or additional furnace XP, and Silk Touch is incompatible (forced combinations preserve Silk Touch).

All four join vanilla's enchanting-table and librarian-book pools. Table weight is 1 (rare). Tree Chop and Miner's Sweep I retain minimum enchantment power25; Sweep II requires30 (maximum cost bands55/60). Librarians use vanilla selection; no guaranteed book or fixed percentage is promised. Matching books/tools combine through ordinary compatible anvil work, up to each enchantment's maximum level, paying the normal capped cost. New offers/rolls can include these books; existing villager offers are not replaced. Experimental trade-rebalance uses separate biome pools and is not altered by this mod.

## Personal toggles (1.4.0)

`/enchants` opens a vanilla one-row chest menu with three locked tool icons: Miner's Sweep, Tree Chop and Harvester Sweep (farmer sweep). Each shows your current ON/OFF state. Click an icon to change only your own behavior; no operator permission, cheats or client mod is required. Inventory transfers, number keys, dropping, dragging, double-click collection and stale/replayed menu actions cannot extract icons or change anyone else's preferences. If another mod owns `/enchants`, the fallback command is `/serverenchantments`.

Direct self commands are `/enchants toggle miner`, `/enchants toggle tree` and `/enchants toggle harvester`. An optional client can bind keys to these vanilla commands; no custom network payload or client dependency is required.

Vanilla shortcut: crouch and press swap-offhand (normally F) while holding the matching enchanted pickaxe, axe or hoe. This toggles that enchantment's extra harvesting without moving either held stack. Other swaps behave normally. F needs a 25-tick (normally 1.25-second) quiet interval before another toggle: this covers a delayed first OS key repeat, and held repeats keep extending that interval without toggling or flooding status messages. Menu/command inputs use a shorter six-tick debounce. Menus and dead/spectator players do not consume this shortcut.

All three preferences default ON for new players and are isolated by player UUID and world. Atomic files live under `<world>/server-enchantments/player-toggles.<UUID>.properties`; no tool data is changed. A missing file uses defaults; a corrupt/unreadable/oversized existing file disables extra harvesting safely and logs a warning. Failed writes leave the previous live and saved preferences intact. Only a matching disabled job is cancelled; other enchantment jobs and other players remain unchanged. OFF restores ordinary single-block breaking, including ordinary young-crop breaking and no automatic seed use/replanting. Existing enchantments, levels, names, durability, damage/mining attributes, Efficiency, Fortune, Unbreaking and Smelter are untouched. Sneaking still temporarily bypasses extra harvesting even when the preference is ON.

## Survival anvil prices

Version 1.1.0 caps valid single-item survival anvil work at **39 levels**, below vanilla's “Too Expensive!” threshold. Lower prices, including a basic one-level rename, stay unchanged. Valid expensive repairs and enchantment combinations keep their ordinary output and require the capped XP payment. Material consumption, incompatibility checks, prior-work growth, pickup authorization and anvil damage remain native. No creative permission or free-output bypass is added. Vanilla's special rejection of stacked enchantment inputs is preserved. Creative behavior is unchanged. The price cap is fixed at 39.

The cap runs only for authoritative `ServerPlayer` menus, including an integrated single-player server. Client-side menu calculations are untouched: installing the mod locally does not invent cheaper prices while joining an unrelated server without it. The server synchronizes the actual result and cost through the ordinary menu protocol.

## Bounded harvesting

Version1.2.0 starts dispatching at the successful native original-break RETURN instead of deliberately spacing each extra block one tick apart. This hook is intentionally later than Fabric's AFTER event in26.2: native tool damage and original drops must finish before any extra block is attempted. A tool with only one durability left therefore breaks on the original block and never earns a free extra break. Small trees and both Sweep shapes can complete before that original native call returns. Full-tree validation still happens before any additional tree log is broken. Jobs rotate after at most32 inspected positions or one block probe, except for the bounded atomic small-job case below; queued jobs retain their place ahead of new arrivals. Unfinished work continues at the end of the tick or on following ticks.

The shared global budget resets only at START_SERVER_TICK; immediate callbacks and END_SERVER_TICK spend the same remaining budget. Defaults are8 player jobs,1024 scanned positions and32 attempted extra-block probes per tick, plus a2ms cumulative soft time slice. Skipped or denied positions consume the probe budget too. A completely planned job with at most8 remaining extras (including Sweep II) runs as one bounded atomic batch only if it has enough global probe credits and time remains when dispatch begins. The entire elapsed batch is charged afterward; exceeding the soft slice stops other jobs for that tick. Protection, tool changes/breakage and native cancellation still stop the batch immediately, before further extras.

The2ms slice counts actual dispatch work, not idle time between player actions. It is not a hard wall-clock maximum: one native call, a32-position scan quantum or the bounded8-extra atomic batch cannot be preempted mid-operation, so expensive modded callbacks can exceed it. Hard global scan/probe counts remain enforced. Large jobs, exhausted credit pools or already-exhausted time use bounded queued fallback; there is no unlimited all-tree burst. Immediate completion is not guaranteed under congestion or when a tree cannot be fully validated within the available scan/time budget.

At most128 logs including the manually mined center,12 blocks horizontal distance,8 blocks below and40 above the origin are supported. Oversized or partially unloaded trees are left intact apart from the block already mined by the player. No terrain is loaded or generated for harvesting.

Every extra block uses the current player's native `gameMode.destroyBlock`, so Fabric BEFORE cancellation, adventure/build permissions, spawn protection, drops, tool damage, enchantments and Unbreaking remain authoritative. Containers/block entities, unbreakable blocks and blocks requiring a better tool are skipped. Miner's Sweep also skips blocks more than 1.5 times harder than the original. Breaking a tool, switching tools, sneaking, dying, disconnecting, changing dimension or moving over 36 blocks from the origin stops the job. Jobs expire after 30 seconds of server ticks. Pending jobs are never persisted or resumed after a restart.

Tree Chop requires matching nonpersistent natural leaves and a trunk rooted on the dirt tag. Only unstripped overworld log types qualify; full-bark wood and nether stems do not. Player-placed log markers are saved with the world (up to 200,000 per dimension; saturation disables tree felling in that dimension rather than forgetting markers). Minecraft does not retain historical placement provenance: buildings placed before this mod, piston-moved logs and command-placed logs cannot be identified perfectly. The grounded-tree/leaf checks reduce this ambiguity but are not proof of natural generation. Use sneak near builds you want to preserve.

## Configuration

Optional `config/server-enchantments.properties`, read at server start:

```properties
max-tree-logs=128
breaks-per-tick=32
scans-per-tick=1024
max-jobs=8
```

Hard maximums are128 logs,64 probes/tick,4096 scans/tick and16 jobs. Reducing limits is supported; existing explicitly configured limits are respected, so an old breaks-per-tick=4 configuration will deliberately spread Sweep II over multiple ticks. No configuration file is created or overwritten automatically. The table/trade availability and rarity are standard datapack JSON resources and can be overridden with a server datapack.

Use vanilla `/enchant <player> serverenchantments:cheery_chop 1` while holding an axe, or `/enchant <player> serverenchantments:wide_miner 1` / `2` while holding a pickaxe, for an operator test. Automatic harvesting must be excluded from heuristic anti-cheat break-rate/reach evidence using the narrow `ServerEnchantmentsFabric.isAutomaticBreak(ServerPlayer)` guard; ordinary player packets remain checked.

Tree Chop keeps the original `serverenchantments:cheery_chop` registry ID for backward compatibility. Miner's Sweep likewise keeps `serverenchantments:wide_miner`. Version1.0.1 corrected Tree Chop's displayed name; version1.0.2 renamed the pickaxe display from Wide Miner to Miner's Sweep. Version1.2.0 changes existing levelI Sweep items/books/offers to the requested three-block row and adds levelII without creating a duplicate enchantment. Existing IDs and levels are retained; vanilla displays I/II because Sweep now has two levels. No save migration is needed.

Build and test with `./build.ps1`. Output: `dist/ServerEnchantments-Fabric-1.4.0+mc26.2.jar`. Requires Fabric Loader0.19.5+, Fabric API0.161.0+26.2 and Java25. Activate server changes at a planned server restart. Client installation requires a game relaunch and enables subsequently opened single-player worlds. Common classes never link client-only types.

Version1.3.0 adds `serverenchantments:harvester_sweep` (levels1–3) and `serverenchantments:smelter` (level1). Existing Tree Chop and Miner's Sweep registry IDs, items and offers remain unchanged. Magnetism and Last Stand are not included.

Harvester shares the existing global harvest budget, job count and cancellation checks with trees and mining. It does not load or generate chunks. Replanting restores age0 only after successful native harvesting and valid soil, space, permission and item checks; each success consumes one inventory planting item and synchronizes the inventory. Fresh drops are left on the ground, not silently taken as free planting supplies. Crop harvesting preserves native durability behavior: these vanilla crops have zero hardness and do not charge hoe durability. Replanting is an authoritative crop restoration, not a burst of simulated player placement packets.

Version1.3.1 fixes rapid harvesting while an earlier neighbor sweep is still queued: each manually broken ripe center gets its own paid restoration at native RETURN, even when the extra-work budget or player job slot is busy. This is at most one restoration per genuine manual break, not a new background scan; its elapsed time is still charged against the shared soft budget before any extras run. Neighbor work retains the same hard limits. Holding attack with a Harvester hoe cannot destroy freshly planted or other immature crops; sneak to deliberately remove them. LevelI, missing seeds, unsuitable soil and denied placement still never create free crops. The native regression runner `node tools/run-harvester-native-test.cjs` uses a separate disposable loopback world and never writes live/client worlds.

The opt-in isolated self-test also runs the transformed native `AnvilMenu` and normal pickup path: costs over40 and exactly40, cheap repair/rename, insufficientXP, exact XP/material consumption, incompatible books, stacked-input rejection, no duplicate output and unchanged creative behavior. Success logs `SERVER_ANVIL_CAP_SELFTEST_PASS` before the existing enchantment pass marker.

## Isolated integration verification

Only in a disposable smoke-test world, add `-Dserverenchantments.selftest=true` before the Java launch target AND create a `server-market-test-fixture` marker in that fresh world's root. Missing marker fails startup rather than running destructive fixtures. Normal startup does not load or run the self-test. It checks the real enchantment registry and table/trade tags, tool compatibility, item save/network codecs, and native block-breaking with a synthetic player: complete small-tree and Sweep harvesting, exact tool durability and drops, Fabric BEFORE cancellation, and stopping at tool break. Temporary blocks are restored and generated drops removed. A successful run logs `SERVER_ENCHANTMENTS_SELFTEST_PASS` and `SERVER_ENCHANTMENT_TOGGLE_NATIVE_TEST_PASS`; failure throws and logs `SERVER_ENCHANTMENTS_SELFTEST_FAIL`. Never enable this fixture flag on a live/player world.
